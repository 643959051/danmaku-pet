# 部署手册（抖音云 Docker 后端）

> 目标读者：负责把云端跑起来的开发者。
> 本文只讲**云端**；开播电脑见《开播手册》。所有平台侧入口与字段以抖音云控制台最新文档为准。

本轮改造后的云端形态：**每实例单 uvicorn Worker / 房间状态在 Redis / 只监听 8000**。实例本身无状态，可随平台扩缩容；多 Worker 仍固定为 1，避免同实例内竞争。

## 2. 本地构建与运行

### 2.1 直接跑 Python（最快的一条路）

```powershell
# 只装云端依赖（不会动桌面小人那套）
.\.conda\env\python.exe -m pip install -r requirements-cloud.txt

# 先看配置是否合法（不启动服务，输出脱敏摘要）
.\.conda\env\python.exe -m danmaku_pet.cloud --check

# 启动
.\.conda\env\python.exe -m danmaku_pet.cloud
```

`--check` 会打印 `protocol_version`、监听地址和一份**脱敏**配置（`public_status()`：不含任何 token、app_secret、DeepSeek Key，只给出 `llm_key_configured: true/false`）。

`APP_ENV` 不设置时默认是 `prod`，而 `prod` 要求 `ADMIN_TOKEN`（≥16 位）与 `CLIENT_TOKEN`，并且默认 `GATEWAY_MODE=douyin_cloud`（需要 `DOUYIN_OPENAPI_BASE_URL`）。本机试跑请显式设 `APP_ENV=dev`。

### 2.2 推荐：`scripts/run_cloud.ps1`

脚本固定了四件事，省掉手工设环境变量：

| 行为 | 值 |
| --- | --- |
| `APP_ENV`（未设置时） | `dev` |
| `GATEWAY_MODE`（未设置时） | `mock` |
| `DEFAULT_ROOM_ID`（未设置时） | `dev-room` |
| `ENABLE_TEST_ENDPOINTS`（未设置时） | `true` |
| `TEMP` / `TMP` | 工作区内 `temp\cloud-temp` |
| `PIP_CACHE_DIR` | 工作区内 `.cache\pip` |

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_cloud.ps1
# 透传参数
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_cloud.ps1 --port 8090 --access-log
```

`dev` 环境下如果没配 `ADMIN_TOKEN` / `CLIENT_TOKEN`，启动时会**生成临时令牌并打印一次**（`【开发模式】本次启动生成了临时管理令牌`）。重启即变，不要把它写进任何文档或脚本。

> 本地还可以把配置写进 `.env.cloud`（`CloudConfig.load()` 会读它，`override=False`，即真实环境变量优先）。这个文件只在开发机用，**不要**放进镜像、不要提交。

### 2.3 docker build

`Dockerfile` 与 `.dockerignore` 都在仓库根目录，构建上下文就是仓库根目录；`deploy/` 只保留
compose 与 cloud env 样例。所有 `COPY` 路径都相对于仓库根目录。

```powershell
docker build -t danmaku-pet-cloud:dev .
docker run --rm -p 8000:8000 `
  -e APP_ENV=dev `
  -e GATEWAY_MODE=mock `
  -e DEFAULT_ROOM_ID=dev-room `
  -e ENABLE_TEST_ENDPOINTS=true `
  danmaku-pet-cloud:dev
```

Dockerfile 的关键点（都能在 `tests/test_deploy.py` 里找到断言）：

- `Dockerfile` 在仓库根目录，构建上下文是仓库根目录；`.dockerignore` 排除密钥（`.env`/`.env.cloud`/`deploy/cloud.env`）、缓存、日志、测试/文档和打包产物；
- 基础镜像 `python:3.11-slim`，只 `pip install -r requirements-cloud.txt`；
- `COPY danmaku_pet/`（含 `client/` 代码，但**不装**其依赖；云端进程从不导入 client）、`data/persona.example.json`，以及根目录 `run.sh`；
- 非 root 用户 `appuser`（uid 10001），`/app/data` 是唯一需要写的目录；
- `EXPOSE 8000`，`HEALTHCHECK` 每 30s 打一次 `http://127.0.0.1:8000/v1/ping`；
- `CMD ["/opt/application/run.sh"]`：平台要求根目录 `run.sh` 复制到 `/opt/application/run.sh` 并具备执行权限；`run.sh` 固定监听 8000。

本机没有 Docker（或 CI 只跑 Python）时，可以先做一次无守护进程校验：

```powershell
.\.conda\env\python.exe .\scripts\verify_dockerfile.py
# JSON 报告
.\.conda\env\python.exe .\scripts\verify_dockerfile.py --json
```

它会检查 Dockerfile 是否在根目录、每条 `COPY` 源是否存在且未被 `.dockerignore` 排除、镜像运行时契约
（基础镜像 / 端口 / CMD / USER / HEALTHCHECK / APP_ENV+CLOUD_*）是否完整，并估算构建上下文里是否有
密钥、缓存、日志、测试/文档或打包产物。**它不能替代真正的 `docker build`**，只能提前发现上下文和
Dockerfile 的低级错误。

要挂载数据目录（人设持久化）时：

```powershell
New-Item -ItemType Directory -Force .\temp\cloud-data | Out-Null
docker run --rm -p 8000:8000 -e APP_ENV=dev -e GATEWAY_MODE=mock `
  -v "${PWD}\temp\cloud-data:/app/data" danmaku-pet-cloud:dev
```

正式环境人设存 Redis，不需要挂 `/app/data`；dev 若坚持用人设文件，挂载点属主需为 uid 10001，否则写本地人设会失败（不影响服务启动）。

### 2.4 docker compose（仅本地开发）

```powershell
docker compose -f deploy/docker-compose.yml up --build
```

compose 里已经固定：`APP_ENV: dev`、`CLOUD_PORT: 8000`、`8000:8000`、`DEFAULT_ROOM_ID: dev-room`、`ENABLE_TEST_ENDPOINTS: "true"`；`GATEWAY_MODE` 取 shell 变量，默认 `mock`。

也可以把变量收进一个 env 文件：

```powershell
Copy-Item deploy\cloud.env.example deploy\cloud.env
notepad deploy\cloud.env      # 本地把 APP_ENV/GATEWAY_MODE 调成 dev + mock/wss，不要填真 Key
docker compose --env-file deploy/cloud.env -f deploy/docker-compose.yml up --build
```

注意：`deploy/cloud.env.example` 的默认值是**生产导向**（`APP_ENV=prod`、`GATEWAY_MODE=douyin_cloud`、空 `DOUYIN_OPENAPI_BASE_URL`）。直接拿它跑本地 compose 会因为 `GATEWAY_MODE=douyin_cloud` 缺 base_url 而启动失败——这正是设计意图（不允许无地址的正式网关）。

### 2.5 起来之后先看这三行

启动日志形如：

```text
  弹幕宠物云端后端  ->  http://0.0.0.0:8000/
  环境=dev  网关=mock  LLM=mock
  健康检查 http://0.0.0.0:8000/v1/ping（详细状态 http://0.0.0.0:8000/api/health）   客户端通道 ws://.../ws/client
```

- `LLM=mock` 表示没有 Key 或在 `LLM_MODE=mock`，**不会**伪装成 DeepSeek；
- `网关=mock` 时不需要任何客户端也能跑通"决策 → 指令 → 回执"；
- `每实例单 Worker；房间状态在 redis/memory` 这行会显示实际状态后端。

## 3. 抖音云部署【人工设置】

以下每一步都只能在抖音云控制台完成，代码侧只能提供"变量名 + 期望值"。

### 3.1 创建服务并选择镜像部署【人工设置】

- 控制台：抖音云 → 目标环境 → 创建服务。
- 部署方式选**镜像**；镜像来源用你实际使用的镜像仓库（平台要求以控制台为准）。
- 服务名建议与房间/业务对应，便于告警定位。
- 记录：环境 ID、服务名、镜像地址与 tag。

**代码落点**：无（部署参数不在代码里）。镜像启动命令已固化在 Dockerfile 的 `CMD ["/opt/application/run.sh"]`；控制台里**不要**再覆盖成 `--workers 4` 之类。平台要求根目录 `run.sh` 复制到 `/opt/application/run.sh` 并保持可执行权限，Dockerfile 已 `chmod a+x`。

### 3.2 容器端口 8000【人工设置】

- 抖音云服务**只能监听 8000**；容器端口填 `8000`，协议 HTTP。端口不对会导致平台冷启动报 `Function cold start timeout`。
- `run.sh` 已固定 `--port 8000`，不要用环境变量把端口改走；`CLOUD_PORT` 仅用于本地/日志展示，默认也是 8000。
- 只暴露这一个端口：云端没有别的入站服务，WebSocket 也复用同一个端口（`/ws`、`/ws/client`）。

**代码落点**：`run.sh`（固定 `--port 8000`）、`CLOUD_PORT`（默认 8000）、`CLOUD_HOST`（默认 `0.0.0.0`）。

### 3.3 存活性探针 `/v1/ping`【人工设置】

- 平台用 `GET /v1/ping` 判断服务存活性：必须**免鉴权**返回 200（否则会被 401/404 判死）。
- 本项目的 `/v1/ping` 返回 `{"ok": true, "status": "ok", "timestamp": ...}`；Dockerfile 内置 `HEALTHCHECK` 也打这个接口。
- 更详细的运行状态仍看 `GET /api/health`（同样免鉴权），字段来自 `cloud/server.py`：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/v1/ping
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

```json
{
  "ok": true,
  "worker_alive": true,
  "environment": "prod",
  "gateway_mode": "wss",
  "version": "0.1.0",
  "protocol_version": 1,
  "rooms": 1,
  "uptime_s": 132.4,
  "timestamp": 1761733333.0
}
```

`ok` 取的是编排器存活状态（`orchestrator.alive`：未在关闭且清理任务还在跑），不是"进程还在"这么弱。

### 3.4 无状态状态存储：Redis【人工设置】

抖音云要求服务无状态、可动态扩缩容。当前云端把房间上下文、待回复、统计、自动回复/暂停、消息/指令去重和人设都放在**外部状态存储**：

- `prod`：必须 `STATE_BACKEND=redis`，并提供 `REDIS_URL` 或平台注入的 `DB_REDIS_*`；两者都没有会启动失败；
- 抖音云 Redis 版本：**选 Redis 6**；代码用到的 `SET NX EX` / `SETEX` / `SCAN` / `EVAL` 在 Redis 5/6/7 都可用，Redis 5 也能跑，但没有必要选更旧的；
- **抖音云会自动注入** `DB_REDIS_ADDRESS`（例如 `10.1.1.123/3306`）、`DB_REDIS_ACCOUNT`、`DB_REDIS_PASSWORD`；代码会拼成 `REDIS_URL`，`REDIS_URL` 留空即可。显式 `REDIS_URL` 优先级更高，只用于本地隧道调试；
- 本地 `deploy/docker-compose.yml` 用的 `redis:7-alpine` 仅用于开发联调；
- `dev`：默认 `STATE_BACKEND=memory`（仅本机，进程退出即丢）；
- 临时降级：`ALLOW_EPHEMERAL_STATE=true` 才允许 prod 内存模式，不推荐；
- 每个实例仍用 `workers=1`（避免同一进程内多 worker 竞争），但**多个实例可以共享 Redis**，请求落到任意实例都能读到同一房间状态；
- 房间锁用 Redis `SET NX PX` + Lua 释放，避免同一房间并发写；
- 房间状态 key 有 TTL（默认 1800s），不再需要进程内空闲回收任务。

**WSS 备用链路**：自建 WebSocket 的活连接仍绑定实例，`GATEWAY_MODE=wss` 只用于单实例开发/备用；正式环境请用 `GATEWAY_MODE=douyin_cloud`，由平台网关维护 room→client 路由。

### 3.5 密钥管理【人工设置】

在抖音云**密钥管理 / 环境变量（加密）**里逐项配置，不要写进镜像、不要写进 `.env` 再 COPY 进去：

| 变量 | 是否必填 | 说明 |
| --- | --- | --- |
| `ADMIN_TOKEN` | **prod 必填**，≥16 位 | 管理端 REST + `/ws` 鉴权；启动时进入日志脱敏名单 |
| `CLIENT_TOKEN` | **prod 必填** | 开播电脑注册用；同样脱敏 |
| `DEEPSEEK_API_KEY` | 有 Key 才填 | 只存在于云端；客户端进程里没有这个字段 |
| `DEEPSEEK_BASE_URL` | 可选 | 默认 `https://api.deepseek.com` |
| `DOUYIN_APP_SECRET` | 接平台后必填 | 取 access_token |
| `DOUYIN_VERIFY_TOKEN` / `DOUYIN_VERIFY_SECRET` | 用对应校验模式时必填 | 入站消息校验 |
| `REDIS_URL` | **prod 必填** | 房间状态/去重/人设；由平台提供持久化 Redis |
| `APP_ENV` | 必填 | `prod` 才启用全部安全校验 |

`APP_ENV=prod` 时缺 `ADMIN_TOKEN`、`CLIENT_TOKEN`、`REDIS_URL` 会**直接启动失败**并打印中文原因，这是有意为之：宁可起不来，也不要裸奔/丢状态。

### 3.6 数据目录 `/app/data`（仅 dev/兼容）

- **正式环境的人设事实来源是 Redis**（`dmp:persona`），不是 `/app/data/persona.json`；
- `dev` 仍可从镜像内 `data/persona.example.json` 播种到 `CLOUD_DATA_DIR`，方便本地编辑；
- `/app/data` 不可写时服务仍能启动（人设回退到内置默认值），不会把本地文件当成必需状态；
- `/api/settings/persona` 写 Redis；dev 内存模式下只在进程内生效。

### 3.7 日志与告警【人工设置】

- 云端日志只输出到**标准输出**（`setup_cloud_logging`，不写文件），由平台采集；
- 已内置脱敏：`ADMIN_TOKEN`、`CLIENT_TOKEN`、`DEEPSEEK_API_KEY`、`DOUYIN_APP_SECRET`、`DOUYIN_VERIFY_SECRET`、`DOUYIN_VERIFY_TOKEN` 只要长度 ≥4，出现即替换成 `***`；
- uvicorn 访问日志**默认关闭**（`--access-log` 才开）：URL 查询串里可能带 `/ws?token=...`；
- 观众昵称和弹幕文本默认**不写日志**（`LOG_VIEWER_DATA=false`），日志里只有 `event_id` / `command_id`；只有确认平台允许后才打开；
- `httpx` / `httpcore` 日志级别被压到 WARNING，避免平台请求刷屏。

建议在控制台配置的告警：

| 告警 | 触发条件 | 含义 |
| --- | --- | --- |
| 健康检查失败 | `/v1/ping` 非 200 或 `/api/health` 的 `ok=false` | 进程挂了或编排器停摆 |
| 5xx 比例 | 持续 >1% | 回执派发失败、内部异常 |
| 重启次数 | 短时间多次重启 | 配置错误（多数是 `ConfigError` 启动即退） |

日志里值得搜的关键字：`配置错误`、`指令下发失败`、`等待客户端回执超时`、`拒绝未通过校验的平台消息`、`抖音云网关未配置`。

### 3.8 资源额度【人工设置】

第一版按小规模估：

| 资源 | 建议 | 依据 |
| --- | --- | --- |
| CPU | 1 核起 | 单进程异步；主要等待 DeepSeek 与网关 |
| 内存 | 512 MB 起 | 每个房间一条队列（上限 `QUEUE_MAX=50`）+ 最近 20 条记录 + 去重缓存 |
| 房间数 | 看 `MAX_ROOMS`（默认 50） | 到上限时先淘汰"最久没有活动且已空闲"的房间；只有所有房间都忙时才拒绝新建 |
| 房间状态回收 | `ROOM_STATE_TTL_SECONDS=1800` | Redis key TTL 自动过期，不再依赖进程内回收任务 |
| 出网 | 需能访问 DeepSeek Base URL | 受限时按平台允许的方式调整 `DEEPSEEK_BASE_URL` |

### 3.9 可回滚镜像版本【人工设置】

- 镜像 tag 用**可追溯**的名字（例如 `cloud-<日期>-<commit 短哈希>`），不要只用 `latest`；
- 在控制台保留上一版可一键回切的部署版本；
- 记录一份"本次发布对应的环境变量差异"，回滚时一起还原（回滚镜像但留着新变量，经常是二次故障的根源）；
- 回滚步骤见第 7 节。

### 3.10 网络：DeepSeek 可达性【人工设置】

云端必须能访问 `DEEPSEEK_BASE_URL`。如果环境出网受限：

1. 先在容器里验证：`docker run --rm danmaku-pet-cloud:dev python -c "import httpx;print(httpx.get('https://api.deepseek.com', timeout=5).status_code)"`；
2. 不通就换平台允许的模型服务地址（改 `DEEPSEEK_BASE_URL`），**不要**改代码；
3. 全都不可达时设 `LLM_MODE=mock`，系统会明确显示"本地模拟"，功能可用但不产生真实模型回复。

## 4. 环境变量全表

来源：`danmaku_pet/cloud/config.py`（唯一权威）。"必填"指**正式环境**。

### 4.1 运行环境

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `APP_ENV` | 是 | `prod` | `dev` / `prod`；非法值直接 `ConfigError` |
| `CLOUD_HOST` | 否 | `0.0.0.0` | 监听地址 |
| `CLOUD_PORT` | 否 | `8000` | 监听端口默认值；镜像内 run.sh 固定 8000，Docker 健康检查也固定打 8000 |
| `LOG_LEVEL` | 否 | `INFO` | 转大写；非法值回落到 INFO |
| `CLOUD_DATA_DIR` | 否 | `<应用根>/data` | 可写数据目录 |
| `PERSONA_PATH` | 否 | `<CLOUD_DATA_DIR>/persona.json` | dev 本地人设；prod 事实来源是 Redis `dmp:persona` |
| `DISPLAY_TIMEZONE` | 否 | `Asia/Shanghai` | 回答"现在几点"用的 IANA 时区；非法值启动即 `ConfigError`。镜像已安装 `tzdata` |
| `LOG_VIEWER_DATA` | 否 | `false` | `false` 时日志只写 `event_id`/`command_id`，不写观众昵称和弹幕文本 |

### 4.2 鉴权

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `ADMIN_TOKEN` | prod 必填，≥16 位 | dev 下自动生成并打印 | 管理端 REST + `/ws?token=` |
| `CLIENT_TOKEN` | prod 必填 | dev 下自动生成并打印 | 客户端 `hello.payload.token` |

### 4.3 决策（DeepSeek）

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `LLM_MODE` | 否 | `auto` | `auto` / `deepseek` / `mock`；`auto` = 有 Key 用 deepseek，否则 mock |
| `DEEPSEEK_API_KEY` | 用真实模型时必填 | 空 | 仅云端持有 |

### 4.8 内容安全

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `DOUYIN_CONTENT_SECURITY_ENABLED` | prod 建议 true | dev `false`，prod `true` | 同时检测弹幕和昵称；开启后需要 `DOUYIN_APP_ID` / `DOUYIN_APP_SECRET` |
| `DOUYIN_CONTENT_SECURITY_BASE_URL` | 否 | `https://developer.toutiao.com` | 沙盒改为 `https://open-sandbox.douyin.com` |
| `DOUYIN_CONTENT_SECURITY_FAIL_CLOSED` | 否 | `true` | 接口不可用时丢弃事件；`false` 时允许文本回复但强制不转语音 |
| `BLOCKED_WORDS` | 否 | 空 | 逗号/分号/竖线分隔；命中即丢弃评论、替换回复 |

| `MAX_REPLY_CHARS` | 否 | `240` | 下限 20 |

平台检测使用小程序 `access_token`（`POST /api/apps/v2/token`）和
`POST /api/v2/tags/text/antidirt`（`X-Token`）。access_token 缓存在 Redis
`dmp:cache:douyin:app-access-token:<appid>`，避免多实例重复获取导致旧 token 提前失效。
弹幕或昵称任一命中 `hit=true` 都会在进入模型/TTS 前丢弃；检测接口不可用时按
`DOUYIN_CONTENT_SECURITY_FAIL_CLOSED` 处理，且永远不会把未检测的昵称转成语音。

## 5. 安全约束

| 约束 | 实现位置 | 怎么验证 |
| --- | --- | --- |
| 镜像不含密钥 | `.dockerignore` 排除 `.env`、`.env.*`（保留 `.env.example`）；Dockerfile 无 `COPY .env` | `docker run --rm danmaku-pet-cloud:dev ls -a /app` |
| 镜像不含本地素材/测试/脚本 | `.dockerignore` 排除 `vendor`、`tests`、`scripts`、`docs`、`temp`、`dist`、`.conda`、`assets` | 同上 |
| 日志不含密钥 | `SecretMaskFilter`（`logging_setup.py`），密钥长度 ≥4 即替换为 `***` | 触发一次 401 或配置 dump，看日志 |
| 云端没有"写 Key"的接口 | `cloud/server.py` 不含 `update_env_file` / `settings_store` / `/api/settings/llm`（测试断言） | `tests/test_deploy.py::test_cloud_server_never_writes_secrets_to_env_files` |
| 管理端必须鉴权 | `TokenAuth.require_admin`，缺失/错误都返回 401 + `WWW-Authenticate: Bearer` | 第 6 节的 401 示例 |
| 测试接口默认关闭 | `require_test_endpoints` → 404 `测试接口在当前环境已关闭（ENABLE_TEST_ENDPOINTS=false）` | prod 下 `POST /api/rooms/x/events/manual` |
| 访问日志默认关闭 | `--access-log` 未传则 `access_log=False` | 启动日志里没有逐条请求 |
| 只读文档端点关闭 | `docs_url=None` / `redoc_url=None` / `openapi_url=None` | `GET /docs` 返回 404 |

补充一条**部署时容易忽略**的事实：`docker-compose.yml` 只用于本地开发，它把 `APP_ENV` 固定成 `dev`；正式环境必须在抖音云控制台创建服务，不要把 compose 文件当生产部署清单。

## 6. 冒烟验证

### 6.1 一键脚本

```powershell
$env:CLOUD_BASE = "http://127.0.0.1:8000"
$env:ADMIN_TOKEN = "<dev 启动日志里打印的 ADMIN_TOKEN>"
$env:ROOM_ID = "dev-room"
.\.conda\env\python.exe scripts\smoke_test.py
```

它会依次验证：`/api/health` → 无令牌访问 `/api/status` 必须 401 → 发一条模拟评论 → 发一个模拟礼物（嘉年华）→ 轮询房间统计直到 `received >= 2` → 断言礼物走的是高优先级剧本（`priority=high`、`motion=spin`）→ 把结果写到 `temp\smoke-result.json` 并打印一行汇总。

成功输出形如：

```json
{"ok": true, "room": "dev-room", "gateway_mode": "mock", "received": 2, "dispatched": 2, "completed": 2, "gift_motion": "spin", "report": "...\\temp\\smoke-result.json"}
```

失败时最后一行会带出网关状态，通常能直接看出是"没客户端"还是"网关未配置"。

### 6.2 手工命令（不依赖脚本）

```powershell
# 1) 存活性 + 详细健康检查（均免鉴权）
Invoke-RestMethod http://127.0.0.1:8000/v1/ping
Invoke-RestMethod http://127.0.0.1:8000/api/health | ConvertTo-Json -Depth 4

# 2) 未带令牌必须 401
try { Invoke-RestMethod http://127.0.0.1:8000/api/status } catch { $_.Exception.Response.StatusCode.value__ }

# 3) 带令牌读全量状态
$headers = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }
$status = Invoke-RestMethod -Headers $headers http://127.0.0.1:8000/api/status
$status.orchestrator.gateway | ConvertTo-Json -Depth 4

# 4) 模拟一条评论（需要 ENABLE_TEST_ENDPOINTS=true）
$body = @{ text = "小鱼，你好呀，挥挥手"; user = "验收" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body)) `
  http://127.0.0.1:8000/api/rooms/dev-room/events/manual

# 5) 模拟一个礼物
$gift = @{ gift_name = "嘉年华"; gift_count = 1; user = "礼物验收" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($gift)) `
  http://127.0.0.1:8000/api/rooms/dev-room/events/gift

# 6) 重新拉一次状态，看最近记录与指标
$status = Invoke-RestMethod -Headers $headers http://127.0.0.1:8000/api/status
$status.orchestrator.rooms[0].recent | Select-Object -First 3
$status.orchestrator.metrics.stages
```

中文请求体务必按上面方式转成 UTF-8 字节，否则 PowerShell 可能给出乱码弹幕——**看到乱码先怀疑编码，不要先怀疑模型**。

### 6.3 断网/无客户端时的预期

- `GATEWAY_MODE=wss` 且没有客户端连接：`send` 返回 `False`，事件状态 `error`，通知"指令下发失败：客户端未连接或网关拒绝"；
- `GATEWAY_MODE=douyin_cloud` 且 `DOUYIN_COMMAND_PUSH_PATH` 为空：日志 `抖音云网关未配置，指令未下发`，状态同上；
- `GATEWAY_MODE=mock`：不需要客户端，按 `GATEWAY_MOCK_ACK_DELAY_SECONDS` 自动回 `completed`（指令已过期则回 `expired`）。

## 7. 回滚步骤

1. **判定**：`/v1/ping` 或 `/api/health` 持续失败 / 5xx 突增 / 指令全量失败，且已排除客户端与令牌问题 → 执行回滚。
2. **选版本**：抖音云控制台 → 服务 → 版本/部署记录 → 选中上一版镜像 tag。
3. **还原变量**：把本次发布改动过的环境变量恢复成上一版取值（尤其 `GATEWAY_MODE`、`*_EXPIRES_SECONDS`、`ENABLE_TEST_ENDPOINTS`）。
4. **重新部署**：每实例单 Worker，端口 8000；房间状态在 Redis，多实例可共享。
5. **验证**：

```powershell
Invoke-RestMethod http://<云端地址>/v1/ping
Invoke-RestMethod http://<云端地址>/api/health | ConvertTo-Json -Depth 3
$headers = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }
Invoke-RestMethod -Headers $headers http://<云端地址>/api/status |
  Select-Object -ExpandProperty config | ConvertTo-Json -Depth 3
```

6. **客户端侧**：如果本次也升级了 `protocol_version`，客户端与服务端**必须同时**回退（版本不兼容时客户端会直接停止重连，日志 `协议版本不兼容`）。
7. **记录**：把"症状 / 判定依据 / 回滚版本 / 验证结果"写进发布记录。

回滚的已知代价：

- Redis 中的房间状态不会因换实例丢失；dev 内存模式才会在重启时丢状态；
- 人设在 Redis（`dmp:persona`），回滚镜像不影响；如果新版本改坏了人设，需要在管理端重新保存一次。

## 8. 上线检查清单

- [ ] `APP_ENV=prod`，`ADMIN_TOKEN`（≥16 位）与 `CLIENT_TOKEN` 都来自密钥管理
- [ ] `GATEWAY_MODE` 与实际能力匹配（未接平台 = `wss`/`mock`，接平台 = `douyin_cloud` + 有效 `DOUYIN_OPENAPI_BASE_URL`）
