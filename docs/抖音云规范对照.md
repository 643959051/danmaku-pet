# 抖音云服务代码规范对照检查

> 检查对象：本仓库的**云端服务**（`danmaku_pet/cloud`，入口 `python -m danmaku_pet.cloud` / 镜像内 `/opt/application/run.sh`）。
> 开播电脑客户端（`danmaku_pet/client`）不部署到抖音云，不适用本清单。
> 规范原文：抖音云《代码规范与风格指南》（2025-12-25 更新）。

## 1. 结论总览

| # | 规范 | 结论 | 实现 |
| --- | --- | --- | --- |
| 1 | 服务必须无状态；状态放远端 Redis/MySQL；启动不依赖本地内存/落盘数据 | **通过**（正式链路） | `STATE_BACKEND=redis` 为 prod 默认；房间上下文/待回复/统计/自动回复/暂停/去重/人设都在 Redis；内存模式只允许 dev 或显式降级 |
| 2 | 只能监听 8000 | **通过** | `run.sh` 固定 `--port 8000`；`CloudConfig` 默认 8000；Dockerfile `EXPOSE 8000`；测试与文档同步 |
| 3 | 根目录 `run.sh`，自定义镜像复制到 `/opt/application/run.sh`，可执行 | **通过**（镜像内） | 根目录 `run.sh`；Dockerfile `COPY` + `chmod a+x` + `CMD ["/opt/application/run.sh"]` |
| 4 | HTTP 服务提供 `GET /v1/ping`，返回 200 | **通过** | `danmaku_pet/cloud/server.py` 的 `GET /v1/ping` 免鉴权返回 200；Docker `HEALTHCHECK` 也打它 |
| 5 | 不鼓励启动后台进程/线程（响应返回后仍有异步任务） | **通过** | 已移除房间 worker/队列等待/空闲回收/任务重试；请求内完成决策+下发；mock 自动回执与模拟循环仅 dev |
| 6 | 默认 UTC；可用 TZ 环境变量或代码设置时区 | **通过** | `DISPLAY_TIMEZONE`（默认 `Asia/Shanghai`）+ `zoneinfo`/`tzdata`；不依赖容器 `TZ`；日志时间戳仍默认 UTC |

**一句话**：六项规范已经按“正式链路”对齐；运维需要保证 **Redis 可用**，并让正式环境使用 **抖音云网关** 而不是自建 WSS 做多实例路由。

## 2. 逐条证据

### 2.1 无状态（规范 1）

**外部状态存储**：`danmaku_pet/cloud/state.py`

| 状态 | 位置 |
| --- | --- |
| 房间上下文（最近 N 轮） | Redis `dmp:room:<room_id>` JSON 的 `memory` |
| 待回复弹幕 | 同上 `pending` |
| 最近事件/统计/当前指令 | 同上 `recent` / `stats` |
| 自动回复、暂停 | 同上 `auto_reply` / `paused` |
| 平台消息去重 | Redis `dmp:dedup:msg:<key>`，`SET NX EX` |
| 指令去重 | Redis `dmp:dedup:cmd:<command_id>`，`SET NX EX` |
| 人设 | Redis `dmp:persona` |
| 房间锁 | Redis `dmp:lock:<room_id>`（SET NX PX + Lua 释放） |

- **启动**：服务启动只依赖环境变量和镜像；房间状态按需从 Redis 读取，不依赖本地内存 cache 或 `/app/data` 的旧文件。
- **实例替换**：`handle_event` / `reply_to` / `handle_result` / `pause` / `clear` 都是“加锁 → 读 Redis → 处理 → 写 Redis”，任意实例都能接着处理。
- **prod 硬校验**：`APP_ENV=prod` 时 `STATE_BACKEND=memory` 会直接 `ConfigError`（除非显式 `ALLOW_EPHEMERAL_STATE=true` 临时降级）；`STATE_BACKEND=redis` 缺 `REDIS_URL` 也会启动失败。
- **人设**：prod 不再读写 `/app/data/persona.json`；从 Redis 读取，管理端保存也写 Redis。`/app/data` 只作为 dev/迁移兜底。

**唯一残留**：自建 WSS 备用链路中，`SessionRegistry` 的 room ↔ socket 是活连接，天然绑定实例。正式链路应使用抖音云网关（平台维护路由）；`GATEWAY_MODE=wss` 只用于单实例开发/备用。此边界已在部署手册标注。

### 2.2 8000 端口（规范 2）

- `run.sh`：
  ```sh
  exec python -m danmaku_pet.cloud --host 0.0.0.0 --port 8000
  ```
- `CloudConfig`：`CLOUD_PORT` 默认 `8000`。
- Dockerfile：`ENV CLOUD_PORT=8000`、`EXPOSE 8000`、`HEALTHCHECK` 固定访问 `127.0.0.1:8000/v1/ping`。
- 代码里没有第二个监听端口；WebSocket 复用 8000。

### 2.3 run.sh（规范 3）

- 仓库根目录 `run.sh`：`#!/bin/sh`、`set -eu`，容器内 `/app/danmaku_pet` 存在时 `cd /app`，否则切到脚本目录（模板部署）。
- Dockerfile：
  ```dockerfile
  COPY run.sh /opt/application/run.sh
  RUN chmod a+x /opt/application/run.sh
  CMD ["/opt/application/run.sh"]
  ```
- **Windows 注意**：Git 在 Windows 上不记录 POSIX 执行位；走“模板部署”时在 Linux 执行 `chmod a+x run.sh`，或提交时 `git add --chmod=+x run.sh`。自定义镜像已由 Dockerfile chmod。

### 2.4 `/v1/ping`（规范 4）

```python
@app.get("/v1/ping")
async def ping() -> dict[str, Any]:
    return {"ok": True, "status": "ok", "timestamp": time.time()}
```

- 无鉴权；固定 200；`/api/health` 作为更详细的运维状态保留。
- 测试：`tests/test_cloud_server.py::test_v1_ping_is_public_and_returns_200`。

### 2.5 无后台任务（规范 5）

已移除：

| 旧后台任务 | 现状 |
| --- | --- |
| 每房间 worker / 事件队列 | 删除；`handle_event` 请求内完成决策 + 下发 |
| 等待客户端回执 `_await_result` | 删除；HTTP 请求只负责下发，回执由 `/ws/client` 独立请求更新 Redis |
| 房间空闲回收 `_prune_loop` | 删除；Redis key TTL + 读取时惰性校验 |
| 平台任务启动重试 | 删除；启动失败直接显示 error，主播手动重试 |
| mock 网关自动回执 | 仅 `GATEWAY_MODE=mock` 开发模式使用；prod 禁止 mock |
| 模拟弹幕循环 | 仅 `ENABLE_TEST_ENDPOINTS=true` 的开发/联调环境；prod 默认关闭 |

`tests/test_cloud_orchestrator.py::test_two_events_dispatch_immediately_without_worker_waiting` 锁定“请求内完成、不等待回执”的行为。

### 2.6 时区（规范 6）

- 业务时间（“现在几点”）使用 `DISPLAY_TIMEZONE`（默认 `Asia/Shanghai`），`danmaku_pet/decision/llm.py::local_now()` 用 `zoneinfo` 计算。
- 镜像 `requirements-cloud.txt` 带 `tzdata`，不依赖基础镜像的系统时区库。
- 日志时间戳仍由 logging 使用进程本地时区，默认 UTC；如需东八区可在平台设置 `TZ=Asia/Shanghai`，但不影响业务时间。
- 未全局改写 `time.Local`；显式时区比修改进程全局更可控。

## 3. 配置与部署

### 3.1 关键环境变量

| 变量 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `STATE_BACKEND` | prod 必须 `redis` | dev `memory` / prod `redis` | 状态存储实现 |
| `REDIS_URL` | `STATE_BACKEND=redis` 时必填 | 空 | 平台提供的 Redis 地址 |
| `ROOM_STATE_TTL_SECONDS` | 否 | `1800` | 房间文档 TTL |
| `ROOM_LOCK_TIMEOUT_SECONDS` | 否 | `20` | 等待房间锁的上限 |
| `ROOM_LOCK_TTL_SECONDS` | 否 | `60` | 房间锁租约，需大于一次模型+下发耗时 |
| `ALLOW_EPHEMERAL_STATE` | 否 | `false` | 仅临时允许 prod 内存模式；正式不要开 |
| `ALLOW_MOCK_GATEWAY` | 否 | `false` | 仅临时允许 prod mock 网关；正式不要开 |

### 3.2 本地验证无状态链路

```powershell
# 启动本地 Redis（有 Docker 时）
docker run --rm -p 6379:6379 redis:7-alpine

$env:APP_ENV="dev"
$env:STATE_BACKEND="redis"
$env:REDIS_URL="redis://127.0.0.1:6379/0"
$env:GATEWAY_MODE="mock"
$env:ADMIN_TOKEN="dev-admin-token-1234567890"
$env:CLIENT_TOKEN="dev-client-token-1234567890"
.\.conda\env\python.exe -m danmaku_pet.cloud --host 127.0.0.1 --port 8000
```

或使用 `deploy/docker-compose.yml`（内置一个临时 Redis；默认 `STATE_BACKEND=memory`，验证无状态时改成 `redis`）。

### 3.3 正式链路

- 正式环境使用 `GATEWAY_MODE=douyin_cloud`（抖音云网关），不要依赖自建 WSS 做多实例路由。
- Redis 用平台提供的持久化实例；不要把 Redis 放在容器本地磁盘。
- 每个实例无状态，可按平台策略扩缩容；客户端回执到达任意实例都会写同一份 Redis。
