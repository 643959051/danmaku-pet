# 平台设置清单（阶段 0）

> 适用版本：云端 Docker 后端 + 开播电脑 Windows 客户端（本仓库当前代码）。
> 读者：开发者（需要知道"平台没给时程序会怎么报错"）与主播/运营（需要知道"去哪个控制台点什么"）。
> 平台侧的一切名称、入口、字段与审核要求，**以抖音开放平台 / 抖音云控制台最新文档为准**；本文只记录"必须人工完成什么、代码在哪里等它"。

标记约定：

- **【人工设置】**：只能在平台控制台或开播电脑上完成，改代码不会自动生效。
- **【双方联调】**：平台设置与代码都到位后，需要两端一起验证。
- **【验收】**：阶段 0 的结束条件，未通过就**不能**对外宣称"已接入官方数据"。

---

## 0. 使用方式与一条铁律

1. 按第 1 节的表格逐项推进，每项只填三种状态：`未开始` / `已提交` / `已确认`。
2. 只有 `已确认` 的项才允许填写对应的 `DOUYIN_*` 环境变量。
3. 拿不准的项保持为空——**空值会报错，猜一个值会静默连错地址**，后者更难排查。

**铁律：未拿到权限时不得写死官方接口。**

代码里所有官方 HTTP 调用只有一处（`danmaku_pet/douyin/openapi.py`），每个路径都来自环境变量：

| 缺失的变量 | 触发时机 | 程序行为 |
| --- | --- | --- |
| `DOUYIN_OPENAPI_BASE_URL` | 任何一次平台调用 | 抛 `PlatformNotConfigured`，日志 `未配置 DOUYIN_OPENAPI_BASE_URL：请按抖音开放平台最新文档填写` |
| `DOUYIN_TOKEN_PATH` | 首次取 access_token | 抛 `PlatformNotConfigured`，日志 `未配置 DOUYIN_TOKEN_PATH：平台凭证获取方式确认后再启用官方接口` |
| `DOUYIN_TASK_START_PATH` / `DOUYIN_TASK_STOP_PATH` / `DOUYIN_TASK_STATUS_PATH` | 启动/停止/查询评论礼物任务 | 抛 `PlatformNotConfigured`；管理端调用 `POST /api/douyin/tasks/start` 直接返回 **409** |
| `DOUYIN_COMMAND_PUSH_PATH` | 云端向抖音云网关下发表演指令 | 抛 `PlatformNotConfigured`；`GATEWAY_MODE=douyin_cloud` 下 `send()` 返回 `False`，事件状态记为 `error`，日志 `抖音云网关未配置，指令未下发` |
| `DOUYIN_COMMAND_INTERRUPT_PATH` | 主播点"立刻打断" | 打断只在本进程生效，网关侧未下发，返回 `delivered=false` |

另外还有两条**启动即失败**的硬校验（`danmaku_pet/cloud/config.py`）：

- `GATEWAY_MODE=douyin_cloud` 但 `DOUYIN_OPENAPI_BASE_URL` 为空 → 直接 `ConfigError`，容器起不来。
- `APP_ENV=prod` 且 `DOUYIN_VERIFY_MODE=disabled` → 直接 `ConfigError`。

所以"能力没确认"的正确姿势是：`APP_ENV=prod` + `GATEWAY_MODE=wss`（或 `mock`），把 `DOUYIN_*` 全部留空。

## 2. 开发者入驻与资质【人工设置】

**为什么需要**：没有完成入驻的开发者主体，无法创建应用、无法申请任何互动数据权限，后面 8 项全部卡住。

**在哪个控制台做**：抖音开放平台 → 开发者入驻 / 资质认证。

**代码侧对应**：没有。这一项不产生任何环境变量，是纯粹的前置条件。

**未完成时如何降级**：无法降级。此阶段可以并行做的是"模拟链路"：本地起云端（默认 `APP_ENV=dev`、`GATEWAY_MODE=mock`），用 `scripts/make_mock_commands.py` 生成指令文件让客户端执行，见《开播手册》第 5 节。

**完成判据**：控制台能看到已认证的开发者主体，并能点击创建应用。

## 3. 创建应用 / 玩法【人工设置】

**为什么需要**：`DOUYIN_APP_ID` / `DOUYIN_APP_SECRET` 是云端访问平台的唯一身份；`DOUYIN_VERIFY_TOKEN` / `DOUYIN_VERIFY_SECRET` 则用于校验平台推给我们的消息。

**在哪个控制台做**：抖音开放平台 → 创建应用或玩法 → 记录 App ID / App Secret（Secret 只显示一次，直接存进抖音云密钥管理，不要写进仓库）。

**代码侧对应**：

| 变量 | 读取位置 | 用途 |
| --- | --- | --- |
| `DOUYIN_APP_ID` | `danmaku_pet/cloud/config.py` → `DouyinSettings` | 取 access_token 的请求体 |
| `DOUYIN_APP_SECRET` | 同上 | 同上；启动时进入日志脱敏名单 |
| `DOUYIN_VERIFY_TOKEN` / `DOUYIN_VERIFY_SECRET` | 同上 | `danmaku_pet/douyin/verifier.py` 校验入站消息 |

`DouyinSettings.configured` 的判定是 `base_url and app_id and app_secret` 三者齐全，管理端 `/api/status` 的 `config.douyin.configured` 就是它。

**内容安全检测**：正式环境默认 `DOUYIN_CONTENT_SECURITY_ENABLED=true`，会用同一组
`DOUYIN_APP_ID` / `DOUYIN_APP_SECRET` 调 `POST /api/apps/v2/token` 和
`POST /api/v2/tags/text/antidirt`，同时检测弹幕与昵称。未配置这两项时 prod 会启动失败；
dev 默认关闭，若手动打开也必须配置 App ID/Secret。检测不通过的事件在进入模型/TTS 前丢弃。

**未完成时如何降级**：`APP_ENV=dev`，三个变量留空；`DOUYIN_VERIFY_MODE` 在 dev 下可以设 `disabled`（prod 禁止）。此时平台推送入口仍存在，但不会被真实平台调用。

**完成判据**：App ID / Secret 已存入抖音云密钥管理，本机只有占位。

## 4. 类目判断：互动插件 vs 弹幕小玩法【人工设置】

**为什么需要**：这两类在平台侧是不同的产品形态，直接决定"客户端能不能是本地 EXE""启动参数从哪来""画面归谁"。**判断错了，后面所有联调都要重做。**

**在哪个控制台做**：抖音开放平台 → 类目 / 玩法类型选择，并与平台对接人确认。

**判断表**（对照《改造计划》阶段 0）：

| 你的实际直播形态 | 建议申报 | 依据 |
| --- | --- | --- |
| 主播本人/原有直播内容是主体，小人只是辅助互动区域 | 互动插件（主播 AI 弹幕助播桌宠） | 小人不是直播主体 |
| 直播画面基本只有小人或游戏画面，观众主要靠弹幕/礼物控制表演 | 重新评估是否按**弹幕小玩法**申报 | 交互主体是玩法本身 |

**代码侧对应**：

- `danmaku_pet/client/startup.py` 的 `LAUNCH_KEY_MAP` 与 `--launch` 参数就是为"平台把参数传进来"准备的，键名映射**等类目确认后**才最终固定。
- 若类目要求"画面由平台托管"，则本地小人渲染方案（`execution/dafeiyu.py` + 直播伴侣采集）需要重新评估。
- 若类目允许本地 EXE，则第 7、8 项继续。

**未完成时如何降级**：不写死任何键名。当前实现会接受任意 `--key=value` 并保留在 `config.platform_params`（诊断里显示为 `platform_param_keys`），已知别名才映射到 `room_id` / `client_id` / `cloud_url` / `client_token`。等平台给出正式名字，只改 `LAUNCH_KEY_MAP` 一处。

**完成判据**：书面确认"属于哪一类 + 是否允许本地 EXE"。

## 5. 评论互动数据权限【人工设置】

**为什么需要**：弹幕内容不是连上就能读的，必须先获得评论互动数据能力，平台才会把评论推到我们的接收地址。

**在哪个控制台做**：抖音开放平台 → 能力/权限申请（评论互动数据）。同时确认：

1. 推送方式（HTTP 回调 / 长连接 / 云网关）；
2. 是否由平台管理"任务"（启动/停止/查询）；
3. 回调地址是否支持自定义路径；
4. 鉴权方式（自定义头 or 签名）。

**代码侧对应**：

| 代码位置 | 作用 |
| --- | --- |
| `danmaku_pet/douyin/receiver.py` | 入站路由：`POST /api/douyin/events/comment`、`/api/douyin/events/gift`、`/api/douyin/events/{kind}`；`?room_id=` 可覆盖房间 |
| `danmaku_pet/douyin/verifier.py` | `disabled` / `header` / `hmac` 三种校验；`hmac` = `HMAC_SHA256(secret, timestamp + "." + body)` |
| `danmaku_pet/douyin/adapter.py` | 官方字段 → 统一 `Event`，字段名用候选列表容错，不绑死某版文档 |
| `danmaku_pet/douyin/dedup.py` | `message_id` 优先去重，缺失时用"受控复合键"（同一用户同一秒同一内容合并） |
| `danmaku_pet/douyin/tasks.py` | 评论任务的启动 / 停止 / 重试（指数退避，最多 3 次） |
| `DOUYIN_TASK_*_PATH` | 任务接口路径，全部由人工填写 |

**未完成时如何降级**：

1. 云端 `ENABLE_TEST_ENDPOINTS=true`（dev 默认开），用
   `POST /api/rooms/dev-room/events/manual` 直接注入一条"弹幕"；
2. 或 `POST /api/simulator/start` 起模拟循环；
3. 若只是验证客户端执行，用 `--transport static` + `scripts/make_mock_commands.py`，连云端都不需要。

**注意**：`receiver` 的路径是**我们自己的**路由。平台要求填回调地址时，按控制台实际格式拼接（例如 `https://<云端地址>/api/douyin/events/comment`）；若平台不支持自定义路径，需要先在 `receiver.router()` 里加对应路由，**不要**靠反向代理硬改。

**完成判据**：拿到"字段样例 + 推送方式 + 鉴权方式 + 任务接口路径"四项，且能写进 `deploy/cloud.env.example` 的注释里。

## 6. 礼物互动数据权限【人工设置】

**为什么需要**：礼物事件要抢占当前表演并走高优先级剧本，和评论是**分别申请**的两项能力。

**在哪个控制台做**：抖音开放平台 → 能力/权限申请（礼物互动数据）。

**代码侧对应**：

- 接收：`POST /api/douyin/events/gift`（同一个 `receiver`）；
- 转换：`DouyinEventAdapter.from_gift()` 提取 `gift.id / gift.name / repeat_count`，缺失时 `422`；
- 匹配：`danmaku_pet/decision/gifts.py` 优先用 `gift_id` 查 `GIFT_ID_MAP`，没命中再看名字，最后落到未知礼物的默认剧本；
- 配置：`GIFT_ID_MAP`，格式 `giftIdA=嘉年华,giftIdB=火箭`（逗号或分号分隔，`=` 两侧空格会被去掉）。

**未完成时如何降级**：

1. 手动礼物：`POST /api/rooms/dev-room/events/gift`，body 可只给 `gift_name`；
2. 礼物 ID 未知时保持 `GIFT_ID_MAP` 为空，代码会按名字匹配内置别名（"火箭""嘉年华""玫瑰"等），并记录 `gift_id_map_size=0`。

**完成判据**：拿到礼物字段样例 + 主要礼物的 `gift_id` 列表，并填入 `GIFT_ID_MAP`（**不要**在代码里硬编码 ID）。

## 7. 客户端 EXE 形态确认【人工设置】

**为什么需要**：决定"主播拿到的是安装包还是 exe""谁负责升级""是否允许本地窗口被采集"。

**在哪个控制台做**：抖音开放平台（类目/客户端规范）+ 与平台对接人确认；本地验证在开播电脑上做。

**代码侧对应**：

| 事实 | 位置 |
| --- | --- |
| 打包产物是 onedir 便携目录，唯一入口 `DanmakuPet.exe` | `packaging/DanmakuPet.spec`、`packaging/launcher.py` |
| 打包只收客户端：spec 里出现 `web/client`，**不含** `danmaku_pet/decision` 与 `danmaku_pet.cloud` | 同上（`tests/test_deploy.py` 断言） |
| 进程内没有任何 DeepSeek Key 字段 | `danmaku_pet/client/__main__.py`、`client/status_server.py` |
| 普通用户权限运行即可 | 无管理员清单；`--check-browser` 会报完整性级别 |

**未完成时如何降级**：先用源码运行 `python -m danmaku_pet.client` 联调，确认功能后再打包；正式分发前用 `scripts/build_exe.ps1 -Clean` 自测。

**完成判据**：平台书面确认 exe 形态可用（或给出替代分发方式），并明确"是否需要签名/安装器"。

## 8. 抖音云与云网关【人工设置】

**为什么需要**：正式下行链路优先走抖音云网关；它同时决定云端地址、端口、内网访问方式和密钥注入方式。

**在哪个控制台做**：抖音云控制台 → 开通环境 → 创建服务 → 镜像部署 → 配置端口/健康检查/密钥。

**代码侧对应**：

| 项 | 代码位置 | 说明 |
| --- | --- | --- |
| 监听端口 | `run.sh` 固定 `--port 8000`；`CLOUD_PORT` 默认 `8000` | Dockerfile `EXPOSE 8000`、`HEALTHCHECK` 打 `/v1/ping` |
| 存活性探针 | `GET /v1/ping` | 平台要求：免鉴权返回 200；`/api/health` 保留为详细状态 |
| 详细健康检查 | `GET /api/health` | 免鉴权，返回 `ok/worker_alive/environment/gateway_mode/version/protocol_version/rooms/uptime_s` |
| 无状态状态存储 | `STATE_BACKEND=redis`、`REDIS_URL`；`danmaku_pet/cloud/state.py` | prod 强制 Redis；房间上下文/待回复/去重/人设都外置，见《抖音云规范对照》 |
| 网关模式 | `GATEWAY_MODE`，取值 `mock` / `wss` / `douyin_cloud` | prod 默认 `douyin_cloud`，需要 `DOUYIN_OPENAPI_BASE_URL` |
| 密钥 | 抖音云密钥管理 | `ADMIN_TOKEN`、`CLIENT_TOKEN`、`DEEPSEEK_API_KEY`、`DOUYIN_APP_SECRET`、`DOUYIN_VERIFY_SECRET` 等 |
| 数据目录 | `CLOUD_DATA_DIR`，镜像里 `/app/data` | 仅 dev 人设兜底；prod 人设在 Redis，不作为必需状态 |

具体步骤、环境变量全表、冒烟与回滚见《部署手册》。

**未完成时如何降级**：`GATEWAY_MODE=wss`（自建 WebSocket，开发/备用）或 `mock`（不需要客户端，自动回执）。两者与正式网关实现完全隔离，切换只改一个变量。

**完成判据**：云端服务能起、`/v1/ping` 与 `/api/health` 返回 200、密钥全部来自密钥管理、有一版可回滚镜像。

## 9. 客户端启动参数 / 鉴权 / 测试账号 / 自测工具【人工设置】

**为什么需要**：平台以什么方式把"哪个直播间、连哪个云端、用什么令牌"告诉客户端，直接决定 `startup.py` 的最终契约。

**在哪个控制台做**：抖音开放平台 → 客户端/插件启动配置、测试账号管理、自测工具。

**需要问到的最小信息集**：

1. 启动参数**确切的键名**（例如房间号到底叫 `room_id` 还是 `roomId`）；
2. 参数是命令行、环境变量还是配置文件；
3. 客户端鉴权是"每次启动一次性 token"还是"固定 token"；
4. 测试账号如何登录、如何挂载插件；
5. 自测工具在哪、能测哪几段（评论 / 礼物 / 下发）。

**代码侧对应**：

| 机制 | 位置 | 说明 |
| --- | --- | --- |
| 显式参数 | `--room-id --client-id --cloud-url --client-token` | 一定可用，不依赖平台 |
| 平台键值对 | `--launch key=value`（可重复）+ 未知 `--key=value` | 已知别名映射，未知键保留在 `platform_param_keys` |
| 客户端鉴权 | `CLIENT_TOKEN` → WebSocket `hello.payload.token` | 云端 `TokenAuth.client_allowed()` 常量时间比较 |
| 管理端鉴权 | `ADMIN_TOKEN` → `Authorization: Bearer` 或 `x-admin-token` | 401 时返回 `管理接口需要有效令牌` |

**未完成时如何降级**：一律用显式参数（`--room-id/--cloud-url/--client-token`），或 `.env` 里的 `ROOM_ID/CLOUD_URL/CLIENT_TOKEN`。`--launch` 的别名只是"提前适配"，**不是**已确认契约。

**完成判据**：拿到键名清单 + 鉴权方式 + 测试账号 + 自测工具入口，并把键名补进 `LAUNCH_KEY_MAP`。

## 10. 权限未到位时的降级矩阵

| 缺什么 | 用哪个降级 | 怎么起 | 能验收什么 | 不能验收什么 |
| --- | --- | --- | --- | --- |
| 评论/礼物权限 | 模拟接口 | `APP_ENV=dev`，`ENABLE_TEST_ENDPOINTS=true`，`POST /api/rooms/{room}/events/manual` 或 `/events/gift` | 决策、指令生成、网关回执、指标 | 真实字段、真实频次、平台去重 |
| 客户端通道 | `GATEWAY_MODE=mock` | `scripts/run_cloud.ps1`（默认 dev+mock），`GATEWAY_MOCK_AUTO_ACK=true` | 云端整条决策链路（自动回执 `completed`） | 本地语音/动作 |
| 客户端通道 | `GATEWAY_MODE=wss` | 云端 wss + 客户端 `--transport websocket` | 端到端下发、回执、打断 | 正式网关行为 |
| 云端整体 | `--transport static` | `scripts/make_mock_commands.py` → `--static-commands` | 本地 TTS/动作/抢占/过期 | 云端决策 |
| 平台启动参数 | 显式参数 | `--room-id ... --cloud-url ... --client-token ...` | 全部本地功能 | "平台自动拉起"体验 |
| 类目未定 | 不写死 | 保留 `platform_params` 诊断 | 开发可继续 | 正式提审 |
