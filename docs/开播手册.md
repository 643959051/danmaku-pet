# 开播手册（Windows 客户端 + 直播伴侣）

> 读者：主播（照着做就能开播）与开发者（照着做就能联调）。
> 云端怎么部署见《部署手册》。本手册里的"平台相关"都**以抖音开放平台/直播伴侣最新版本为准**。

本轮改造后的分工很明确：**云端负责"说什么、做什么"，开播电脑只负责"发出声音、做出动作"**。客户端进程里没有 DeepSeek Key，也没有任何模型调用代码。

---

## 0. 开播前 5 分钟检查（老手只看这一节）

```powershell
# 1) 云端活着吗
Invoke-RestMethod http://<云端地址>/v1/ping
Invoke-RestMethod http://<云端地址>/api/health | ConvertTo-Json -Depth 3

# 2) 客户端配置有没有硬伤（不会启动服务）
.\dist\DanmakuPet\DanmakuPet.exe --check

# 3) 起客户端
.\dist\DanmakuPet\DanmakuPet.exe --room-id <room_id> --cloud-url wss://<云端地址>/ws/client --client-token <CLIENT_TOKEN>
```

打开 `http://127.0.0.1:8787/`，确认四件事：`连接 online`、`房间` 正确、`桌宠 ready`、`音频 就绪`。四项里任何一项不对，先看《故障排查》。

## 1. 开播电脑准备【人工设置】

### 1.1 一台稳定的 Windows 电脑

**为什么**：客户端要长时间挂着，桌宠是原生窗口，需要显卡/桌面会话正常。

- Windows 10/11 64 位，有可用的桌面会话（**不要**用无桌面的服务器核心版或纯 RDP 断连会话，Qt 窗口会画不出来）；
- 电源计划不要休眠；直播期间不要自动更新重启；
- 磁盘留出 ≥2 GB：`assets\tts_cache`（语音缓存）、`temp\logs`（日志，单文件 2 MB × 3 个滚动）、打包版本体。

**验证**：

```powershell
Get-ComputerInfo | Select-Object WindowsProductName, OsHardwareAbstractionLayer
(Get-PSDrive D).Free / 1GB
```

### 1.2 普通用户权限运行【人工设置】

**为什么**：客户端不需要管理员权限；用管理员跑反而会让"客户端 → 浏览器/直播伴侣"之间出现完整性级别隔离，自动开页面会静默失败。

- 用普通账号登录开播电脑，直接双击 exe 或从开始菜单开 PowerShell；
- 自查当前窗口的完整性级别：

```powershell
whoami /groups | findstr /i mandatory
```

显示 `Mandatory Label\Medium Mandatory Level` 才是普通交互式会话；`Low` 说明这个终端是受限进程（沙箱/自动化里启动的），浏览器与窗口采集都会出问题。

### 1.3 安装直播伴侣并用测试账号登录【人工设置】

- 安装官方直播伴侣，用**已获得互动数据权限的测试账号**登录；
- 先做一次空播（不挂插件）确认伴侣本身能正常推流；
- 开播前确认账号已具备本项目的插件/玩法挂载资格（这一项在平台侧，客户端无法绕过）。

### 1.4 EdgeTTS 所需网络【人工设置】

**为什么**：语音是**本地**合成的，但 EdgeTTS 需要访问微软的在线语音服务；不通就只能静音表演。

```powershell
# 在开播电脑上验证到语音服务 443 端口是否可达
Test-NetConnection speech.platform.bing.com -Port 443 | Select-Object ComputerName, TcpTestSucceeded
```

- 公司网/酒店网常拦这类域名，必要时换网络或用手机热点验证一次；
- 完全不通也能开播：TTS 失败会记 `tts_failed`、用文本长度估算时长做**静音动作**，不会阻塞队列，但直播体验会明显变差。

### 1.5 音频输出设备【人工设置】

**为什么**：直播伴侣要采集"系统声音"或指定设备，设备选错就是"画面在动但没声音"。

1. 右键任务栏音量 → 声音设置 → 输出，选**直播伴侣将要采集的那个设备**（物理声卡或虚拟声卡）；
2. 把客户端的声音固定到这个设备（Windows 设置 → 应用音量/输出设备，或系统默认输出）；
3. 记下设备名，写进开播检查表。

客户端的 `pygame` mixer 用的是系统默认输出设备；如果 mixer 初始化失败，本地状态页会显示"音频设备未初始化"并给出原因（例如没有可用输出设备、被独占）。

### 1.6 小人窗口采集【人工设置】

**为什么**：小人是一个**无边框、透明、置顶**的原生窗口，采集方式与普通窗口不同。

1. 启动客户端，等状态页 `桌宠 ready`；
2. 直播伴侣 → 添加素材 → 窗口采集 → 选择标题含 `dsh-dafeiyu` / `大肥鱼` 的窗口（标题以实际为准）；
3. 若列表里看不到窗口，改用"采集整个屏幕"再裁剪，或按 1.7 换专用渲染窗口方案；
4. 用 `PET_SCALE`（0.55–1.4，默认 0.8）调大小，别用伴侣的缩放硬拉，会糊。

窗口置顶是客户端行为（原生 helper 始终置顶），所以小人会挡住别的窗口——这是设计意图，直播时把它挪到不遮挡的位置。

### 1.7 透明置顶窗口采集验证【人工设置】

透明窗口在部分采集实现里会变成**黑底**或**全黑**。开播前必须实测一次：

| 现象 | 结论 | 处理 |
| --- | --- | --- |
| 背景透明，只有小人 | 采集正常 | 直接用 |
| 小人周围是黑色方块 | 该采集方式不吃 alpha | 换"屏幕采集 + 裁剪"，或按平台建议改用不透明渲染窗口 |
| 完全黑屏 | 采到了错误窗口（可能是 helper 的隐藏窗口） | 换窗口标题重选，或先用屏幕采集确认小人确实在画 |

**注意**：如果最终必须用不透明窗口，需要开发侧调整渲染（属于代码改动），不是客户端参数能解决的。

### 1.8 系统声音采集，避免回声【人工设置】

**为什么**：如果同时采集"系统声音"和"麦克风"，而麦克风又放在音箱旁边，会形成回声/啸叫。

- 只采**系统声音**（或指定虚拟声卡）时：把麦克风轨道静音，或物理拔掉；
- 需要主播说话时：用耳机，并确认伴侣里"系统声音"和"麦克风"是两条独立轨道；
- 客户端播放走的是系统默认输出，所以"伴侣采系统声音"= 一定能听到小人说话。

验证：让客户端念一句（第 5 节），在伴侣的音频电平表上看到跳动。

### 1.9 一键停止【人工设置】

主播必须能**在任何时候**立刻停住，不需要关窗口：

| 手段 | 操作 | 效果 |
| --- | --- | --- |
| 本地状态页"一键停止" | 点右上角红色按钮 | `POST /api/interrupt`：取消当前表演、清空本地队列、停音频、桌宠回 `IDLE`、给未执行的指令回 `interrupted` |
| 云端管理端"立刻打断" | 管理端按钮 | 云端取消当前指令并向客户端下发 `interrupt` |
| 直接关客户端窗口 / Ctrl+C | 关闭进程 | 立刻静音；云端会在等回执超时后记 `timeout` |

建议把 `http://127.0.0.1:8787/` 加入浏览器书签，直播时留在副屏。

## 2. 客户端启动

### 2.1 源码运行（开发/联调）

```powershell
# 装客户端依赖（含 PySide6 / pygame / edge-tts）
.\.conda\env\python.exe -m pip install -r requirements-client.txt

# 最简：只连云端
.\.conda\env\python.exe -m danmaku_pet.client `
  --room-id dev-room `
  --cloud-url ws://127.0.0.1:8000/ws/client `
  --client-token <CLIENT_TOKEN>
```

用仓库脚本启动（会固定 `TEMP` 到工作区内 `temp\process-temp`）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run.ps1 --room-id dev-room --cloud-url ws://127.0.0.1:8000/ws/client --client-token <CLIENT_TOKEN>
```

`scripts\run.ps1` 调的是 `python -m danmaku_pet`，这个入口现在等价于 `client`（`cloud` 子命令仍可用，见《部署手册》）。

### 2.2 打包版 exe

```powershell
# 打包（首次会自动把 PyInstaller 装进项目环境）
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build_exe.ps1 -Clean

# 运行
.\dist\DanmakuPet\DanmakuPet.exe --room-id dev-room --cloud-url ws://127.0.0.1:8000/ws/client --client-token <CLIENT_TOKEN>
```

产物是**整个 `dist\DanmakuPet` 目录**（绿色版，拷走即用，删除即卸载）：

```text
dist\DanmakuPet\
├─ DanmakuPet.exe     唯一入口，双击即启动
├─ _internal\         运行时、PySide6、本地状态页、桌宠素材
└─ .env.example       配置样例（不含任何 Key）
```

打包版的包内只有客户端（`packaging/DanmakuPet.spec` 收 `web/client`，**不收** `danmaku_pet.cloud` 与 `danmaku_pet.decision`），所以 exe 里不可能有 DeepSeek Key。

桌宠在打包后不是子脚本，而是**同一个 exe 以 `--run-dafeiyu-helper` 重入**运行，由客户端自动拉起，不需要手工操作。

### 2.3 命令行参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--room-id` | 空 | 绑定的直播间 `room_id`；为空会在启动时提示且无法收到指令 |
| `--client-id` | `client-<主机名>` | 客户端标识；同一 client_id 重连会顶掉旧连接 |
| `--cloud-url` | `ws://127.0.0.1:8000/ws/client` | 必须 `ws://` 或 `wss://`，且以 `/ws/client` 结尾 |
| `--client-token` | 空 | 云端 `CLIENT_TOKEN`；`websocket` 模式下必填 |
| `--transport` | `websocket` | `websocket` / `static` / `platform` |
| `--static-commands` | 空 | JSONL 文件路径；**会自动把 transport 切成 `static`** |
| `--host` / `--port` | `127.0.0.1` / `8787` | 本地状态页监听地址/端口 |
| `--no-desktop` | 关 | 不启动桌面小人（只验语音/页面时用） |
| `--no-browser` | 关 | 不自动打开状态页 |
| `--check` | — | 打印环境报告（含 `validation` 问题列表）后退出 |
| `--print-config` | — | 与 `--check` 相同 |
| `--check-browser` | — | 打印浏览器启动环境诊断（完整性级别、能否启动图形程序） |
| `--verbose` | 关 | DEBUG 日志 |
| `--launch KEY=VALUE` | 可重复 | 平台启动参数；未知键保留在诊断里 |

`--check` 输出示例（节选）：

```json
{
  "config": { "room_id": "dev-room", "transport": "websocket", "cloud_token_configured": true },
  "validation": [],
  "helper_exists": true,
  "browser_url": "http://127.0.0.1:8787/"
}
```

`validation` 非空就说明"目前连上也没用"，常见三条：没绑 `room_id`、`cloud_url` 不是 `ws(s)://`、`cloud_url` 没指向 `/ws/client`。

### 2.4 环境变量（等价于参数，可写进 exe 旁的 `.env`）

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `ROOM_ID` | 空 | 直播间房间号 |
| `CLIENT_ID` | 主机名派生 | 客户端标识 |
| `CLOUD_URL` | `ws://127.0.0.1:8000/ws/client` | 云端下行地址 |
| `CLIENT_TOKEN` | 空 | 客户端令牌（**不要**提交到仓库） |
| `CLIENT_TRANSPORT` | `websocket` | `websocket` / `static` / `platform` |
| `STATIC_COMMANDS` | 空 | 静态指令文件 |
| `HEARTBEAT_INTERVAL_SECONDS` | `8` | 心跳间隔（下限 2） |
| `RECONNECT_MIN_SECONDS` / `RECONNECT_MAX_SECONDS` | `1` / `20` | 重连退避上下限 |
| `COMMAND_GRACE_SECONDS` | `0.5` | 过期判定的宽限 |
| `APP_HOST` / `APP_PORT` | `127.0.0.1` / `8787` | 状态页 |
| `AUTO_OPEN_BROWSER` | `true` | 启动后自动开状态页 |
| `LOG_LEVEL` | `INFO` | — |
| `TTS_VOICE` / `TTS_RATE` / `TTS_VOLUME` / `TTS_PITCH` | `zh-CN-XiaoxiaoNeural` / `+8%` / `+0%` / `+0Hz` | EdgeTTS 音色与语速 |
| `TTS_CACHE` | `true` | 复用 `assets\tts_cache` 里的音频 |
| `DESKTOP_PET` | `true` | 是否启动桌宠 |
| `PET_SCALE` | `0.8` | 小人缩放，夹在 0.55–1.4 |
| `DEFAULT_USER` | `观众` | 缺用户名时的兜底 |

参数优先级：命令行 > 环境变量/`.env`。**不要**把 `APP_HOST` 改成 `0.0.0.0`——那等于把状态页暴露到局域网，而它没有任何登录。

### 2.5 用平台启动参数（`--launch`）

平台可能把房间号、云端地址、令牌作为启动参数传进来。当前实现接受两种写法：

```powershell
# 写法 A：显式 --launch
.\dist\DanmakuPet\DanmakuPet.exe --launch room_id=123456 --launch client_token=xxxxx

# 写法 B：任意未识别的 --key=value 也会被收集
.\dist\DanmakuPet\DanmakuPet.exe --roomId=123456 --token=xxxxx
```

已知别名（`danmaku_pet/client/startup.py` 的 `LAUNCH_KEY_MAP`）：

| 平台键 | 映射到 | 备注 |
| --- | --- | --- |
| `room_id` / `roomId` / `room` | `room_id` | 只在本地未设置时生效 |
| `client_id` / `clientId` | `client_id` | 总是覆盖 |
| `cloud_url` / `cloudUrl` / `cloud_ws` / `ws` | `cloud_url` | 总是覆盖 |
| `token` / `client_token` / `clientToken` | `client_token` | 只在本地未设置时生效 |

**边界（诚实说明）**：平台启动参数的**最终键名尚未确认**，以上是"提前适配"，不是契约。所有收到的键都会保留在诊断里（状态页 `/api/status` → `config.platform_param_keys`），未知键不会被丢弃。等平台给出正式名字，只改 `LAUNCH_KEY_MAP` 一处即可。

另外：`hello` 帧里 `platform_params` 固定发送字符串 `"redacted"`，**不会**把原始参数（可能含令牌）发给云端。

## 3. 本地状态页 `http://127.0.0.1:8787/`

页面每 2.5 秒拉一次 `/api/status`（页面不可见时暂停）。打开后按顺序看这 7 项：

| # | 看哪里 | 正常值 | 异常时含义 |
| --- | --- | --- | --- |
| 1 | 顶部 `连接 xxx` | `online` | `connecting`/`reconnecting` = 正在连或连不上；`offline` = 已停止重试（不可重试错误：协议版本不兼容、`platform` 通道未实现、静态指令文件缺失） |
| 2 | 顶部 `房间 xxx` | 你的 room_id | `未绑定` = 没传 `--room-id`，指令全会被丢弃 |
| 3 | "当前表演" | 指令 id、`motion / emotion`、台词、保持毫秒、队列长度 | 有弹幕但一直是 `-` = 没收到指令（看第 4 节） |
| 4 | "语音与音频设备" | `TTS 引擎` 有值、`pygame mixer 已初始化` | `音频错误` 非空 = 设备被占用/无输出设备；`TTS 错误` 非空 = 网络或音色问题（此时是静音动作） |
| 5 | "桌面小人 helper" | `状态 ready`、`进程` 有 pid | `starting` 卡住或 `error` = helper 起不来（素材缺失/端口被占/打包不完整） |
| 6 | "最近错误" + 顶部"诊断"列表 | "没有发现明显问题" | 每条都是可行动的具体问题，不是泛化报错 |
| 7 | 右上角三个按钮 | — | **一键停止**（停当前表演+清队列）、**重新连接**、**保存并重连**（改房间/云端地址） |

补充说明：

- "待发回执"（`outbox`）大于 0 表示云端暂时连不上，回执在本地排队（上限 64 条），恢复后自动补发；
- "房间绑定"只能改 `ROOM_ID` 与 `CLOUD_URL`（写入 exe 旁的 `.env`），**令牌不能从这里改**——这是故意的，避免把令牌写进一个网页能读的文件；
- 页面底部"最近回执"能看到 `accepted → started → completed/interrupted/expired/error` 的完整轨迹，排障时先看这里。

## 4. 本地联调

### 4.1 方式一：`--transport static`（不连云端，验"执行"）

这是阶段 3 的验收路径：**没有云端、没有网络**，只有真实客户端 + 模拟指令。

```powershell
# 1) 生成 3 条模拟云端指令（打招呼 / 火箭 / 转圈）
.\.conda\env\python.exe scripts\make_mock_commands.py

# 2) 用 static 通道回放
.\dist\DanmakuPet\DanmakuPet.exe --transport static --static-commands .\temp\mock-commands.jsonl --room-id dev-room
```

文件里是三条完整 `PerformCommand`（`expires_at = 生成时间 + 3600`，`read_aloud=true`），所以能听到"观众说：……。回复"的完整配音。默认每条间隔 1 秒。

验证点：

- 状态页"当前表演"依次出现 `wave` / 礼物剧本动作 / `spin`；
- `temp\mock-commands.results.jsonl` 追加三行回执（`accepted`、`started`、`completed`）；
- 声音从 1.5 节选定的设备出；
- 桌子上的小人真的动了。

`room_id` 必须与文件里的 `dev-room` **完全一致**，否则客户端日志会打"指令房间不匹配，已忽略"。

### 4.2 方式二：`GATEWAY_MODE=wss`（连真实云端，验"整条链路"）

```powershell
# 终端 A：云端用 wss 模式（默认是 mock，不会下发到客户端）
$env:GATEWAY_MODE = "wss"
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_cloud.ps1

# 记下启动日志里打印的 CLIENT_TOKEN（dev 模式临时生成）
```

```powershell
# 终端 B：客户端
.\dist\DanmakuPet\DanmakuPet.exe `
  --room-id dev-room `
  --cloud-url ws://127.0.0.1:8000/ws/client `
  --client-token <上一步的 CLIENT_TOKEN>
```

```powershell
# 终端 C：从云端发一条模拟评论（需要 ENABLE_TEST_ENDPOINTS=true，run_cloud.ps1 默认开）
# dev 启动日志里同时打印了 ADMIN_TOKEN，这里先用上
$env:ADMIN_TOKEN = "<终端 A 启动日志里的 ADMIN_TOKEN>"
$headers = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }
$body = @{ text = "小鱼，你好呀，挥挥手"; user = "联调" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body)) `
  http://127.0.0.1:8000/api/rooms/dev-room/events/manual
```

**注意一个默认行为**：云端 `AUTO_REPLY=false`（默认），普通弹幕会进"待回复"列表，**不会自动表演**。要立刻看到效果，二选一：

```powershell
# a) 打开自动回复（之后的新弹幕先念再回）
$payload = @{ enabled = $true; room_id = "dev-room" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json" `
  -Body $payload http://127.0.0.1:8000/api/settings/auto-reply

# b) 或者手动"回复上一条"
Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json" `
  -Body "{}" http://127.0.0.1:8000/api/rooms/dev-room/reply
```

礼物不吃这个开关，始终高优先级抢占：`POST /api/rooms/dev-room/events/gift`，body `{"gift_name":"嘉年华"}`。

验证点（与阶段 3/6 验收对应）：

- 云端 `/api/status` 的 `orchestrator.rooms[0].recent[0].result_status` 从 `dispatched` 变成 `completed`；
- 客户端"最近回执"里同一条 `command_id` 也是 `completed`；
- 连续发两条相同内容：第二条被去重（云端 `duplicates` 计数 +1，客户端不重复表演）；
- 点"一键停止"：当前表演立刻中断，回执为 `interrupted`。

### 4.3 方式三：`--transport platform`（当前不可用）

会**立刻**报错并停止重连：

```text
抖音云网关客户端通道尚未接入：请等待平台提供客户端 SDK/启动参数，
当前可先用 --transport websocket（开发/备用）或 --transport static（本地联调）
```

这是有意为之：假装"已连接"会把一条断掉的正式链藏起来。等平台给出规范后在此实现。

## 5. 三条硬边界（不要在开播时踩）

### 5.1 本地没有 DeepSeek Key

- 客户端没有任何填写/保存 Key 的界面，`config.py` 里也没有这个字段；
- `client/` 目录下所有文件都不含 `DEEPSEEK_API_KEY`（`tests/test_deploy.py` 有断言）；
- 断网/云端不可用时，客户端**不会**编出一个"看起来正常"的回复——它只会显示连接失败。

### 5.2 不开入站端口

- 客户端只监听 `127.0.0.1:8787`（回环），不对局域网/公网开放；
- 与云端的连接是客户端**主动**发起的出站 WebSocket，开播电脑不需要公网 IP、不需要端口映射、不需要内网穿透；
- 状态页无登录鉴权，所以**必须**保持 `APP_HOST=127.0.0.1`。

### 5.3 断线重连不会重放过期评论

指令里带的是**绝对过期时间**（评论 8 秒、礼物 30 秒，云端可配）：

- 客户端连上后收到一条已过期的指令 → 不发动作，直接回 `expired`；
- 排队期间过期的指令 → 同样回 `expired`（"排队期间指令已过期"）；
- 好处：网络恢复后不会突然演一条 5 分钟前的弹幕；
- 代价：断线超过有效期的那几条弹幕就是丢了——这是刻意取舍，宁可丢也不要"时空错乱"。

重连行为：退避 1s 起、翻倍、上限 20s；心跳 8 秒一次，连续 24 秒没有任何云端消息判"心跳超时"并重连；本地回执进 `outbox`（最多 64 条），重连后自动补发。
