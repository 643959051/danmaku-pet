# 故障排查

> 按"现象"查，不按"模块"查。每节都是：**怎么确认 → 怎么修**。
> 命令默认在仓库根目录、PowerShell 下执行；`<云端地址>` 换成实际地址。

---

## 0. 先收集这三样，再开始猜

```powershell
# ① 云端活着吗（免鉴权）
Invoke-RestMethod http://<云端地址>/v1/ping
Invoke-RestMethod http://<云端地址>/api/health | ConvertTo-Json -Depth 3

# ② 带令牌看全量状态（配置 / 网关 / 房间 / 指标）
$headers = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }
Invoke-RestMethod -Headers $headers http://<云端地址>/api/status | ConvertTo-Json -Depth 6 > temp\status.json

# ③ 客户端状态页
Start-Process http://127.0.0.1:8787/
```

日志位置：

| 端 | 位置 |
| --- | --- |
| 云端 | 标准输出（抖音云控制台日志页）；本地跑时就是终端 |
| 客户端 | `temp\logs\app.log`（单文件 2 MB，滚动 3 个）＋ 终端输出 |

一个**通用判读顺序**：先看连接（online 吗）→ 再看房间（对得上吗）→ 再看指令（有没有下发）→ 最后看执行（TTS/音频/桌宠）。跳过前面直接查模型，90% 是在浪费时间。

## 1. 云端启动即退出

**怎么确认**

```powershell
.\.conda\env\python.exe -m danmaku_pet.cloud --check
echo $LASTEXITCODE     # 2 = 配置问题
```

启动失败时 stderr 会有一行中文原因，形如 `配置错误：<原因>`，进程退出码 **2**。常见原因（全部来自 `cloud/config.py`）：

| 日志内容 | 触发条件 |
| --- | --- |
| `APP_ENV 必须是 dev/prod，收到 'xxx'` | `APP_ENV` 拼错 |
| `GATEWAY_MODE 必须是 mock/wss/douyin_cloud，收到 'xxx'` | 拼错或用 `websocket`（正确值是 `wss`） |
| `LLM_MODE 必须是 auto/deepseek/mock，收到 'xxx'` | 拼错 |
| `正式环境必须配置至少 16 位的 ADMIN_TOKEN（在抖音云密钥管理中设置）` | `APP_ENV=prod` 且 `ADMIN_TOKEN` 缺失/过短 |
| `正式环境必须配置 CLIENT_TOKEN，用于本地客户端注册` | 同上，客户端令牌缺失 |
| `正式环境禁止 DOUYIN_VERIFY_MODE=disabled，请配置 header 或 hmac` | prod 下关了入站校验 |
| `GATEWAY_MODE=douyin_cloud 需要 DOUYIN_OPENAPI_BASE_URL；平台能力确认前请使用 GATEWAY_MODE=wss 或 mock` | 选了正式网关却没有地址 |
| `DOUYIN_VERIFY_MODE 必须是 disabled/header/hmac，收到 'xxx'` | 拼错 |

另一个"起来又立刻退出"的常见原因不是配置，而是**端口被占**：uvicorn 会打印 `[Errno 10048] error while attempting to bind on address ('0.0.0.0', 8000)`。

**怎么修**

```powershell
# 谁占了 8000
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess
Get-Process -Id <上面查到的 pid> | Select-Object ProcessName, Path

# 换端口验证是否配置问题（换端口后记得同步健康检查）
.\.conda\env\python.exe -m danmaku_pet.cloud --port 8090
```

容器里"启动即退出"还有一个专属原因：`/app/data` 不可写（属主不是 uid 10001），表现为 `Permission denied: '/app/data/persona.json'`。改用命名卷或把 `CLOUD_DATA_DIR` 指到可写目录，见《部署手册》3.6。

## 2. 管理接口返回 401

**怎么确认**

```powershell
# 不带令牌 → 必须 401
try { Invoke-RestMethod http://<云端地址>/api/status } catch { $_.Exception.Response.StatusCode.value__ }

# 带令牌 → 200
$headers = @{ Authorization = "Bearer $env:ADMIN_TOKEN" }
Invoke-RestMethod -Headers $headers http://<云端地址>/api/status | Select-Object -ExpandProperty app
```

401 响应体是 `{"detail":"管理接口需要有效令牌（Authorization: Bearer <ADMIN_TOKEN>）"}`，并带 `WWW-Authenticate: Bearer`。

**怎么修**

1. `$env:ADMIN_TOKEN` 里可能带了引号/空格/换行；`Authorization` 支持 `Bearer <token>`，也支持 `x-admin-token: <token>` 头，两种写法任选；
2. dev 模式的令牌是**每次启动随机生成**的，日志只打印一次，重启就变——去当前终端输出里重新复制；
3. prod 的令牌来自抖音云密钥管理，确认控制台里的值与本地测试用的是同一个；
4. 云端重启过、而你还在用旧令牌 → 换成新值。

管理端 WebSocket 是另一套：`/ws?token=<ADMIN_TOKEN>`（查询串），失败直接以 4401 关闭，浏览器里表现为"页面连不上实时流"。

## 3. 客户端连不上云端

**怎么确认**

```powershell
# 客户端自检：配置/校验问题一目了然
.\dist\DanmakuPet\DanmakuPet.exe --check
```

看 `validation` 数组。同时对照客户端日志与状态页：

| 现象 | 含义 |
| --- | --- |
| 状态页 `连接 connecting` 长期不变 | TCP 没连上（地址/端口/防火墙/云端没起） |
| `连接 reconnecting`，`重连次数` 一直涨 | 连上又被断开（多为令牌错） |
| `连接 offline` 且不再重试 | 不可重试错误（令牌被服务端以 4401 拒绝后仍会重试；**协议版本不兼容**会直接停） |
| 日志 `协议版本不兼容：对端 vX，本端支持 v1~v1` | 云端与客户端版本不一致 |
| 日志 `连接云端失败：...` | DNS/TLS/端口不通 |
| 日志 `云端连接断开：...` | 握手后立刻被关（4401/4400/4406/4408/4409） |

云端 `/ws/client` 的关闭码含义（`cloud/server.py`）：

| 码 | 原因 |
| --- | --- |
| 4400 | 首帧不是合法 `hello`，或缺少 `client_id` / `room_id` |
| 4401 | 客户端令牌不匹配 |
| 4406 | 协议版本不支持 |
| 4408 | 15 秒内没收到 `hello` |
| 4409 | 同一 client_id/房间有更新的连接，旧连接被替换 |

**怎么修**

1. **URL**：必须是 `ws://host:port/ws/client` 或 `wss://.../ws/client`。`--check` 会明确提示"cloud_url 应指向云端的 /ws/client"。
2. **令牌**：`--client-token` 或环境变量 `CLIENT_TOKEN`。dev 下看云端启动日志打印的 `CLIENT_TOKEN=`；prod 下从密钥管理复制。
3. **房间**：`--room-id` 必填。空房间时 `--check` 会报"没有绑定 room_id"；连上也收不到任何指令（云端是**按 room_id 精确投递**的）。
4. **协议版本**：两端都是 `protocol_version=1`。若刚升级过一端，把另一端一起升级——版本不兼容时客户端会**停止重连**而不是死循环，这是刻意设计。
5. **4409 反复出现**：说明同一 `client_id` 有两个进程在抢同一个房间（例如旧窗口没关）。关掉多余的客户端，或给它们不同的 `--client-id`。
6. **云端在容器里时**：`ws://127.0.0.1:8000` 指向的是**你自己这台机器**，不是云端。正式环境要用平台分配的地址，且 `wss://` 需要 TLS。

## 4. 客户端显示 platform 通道不可用

**怎么确认**：日志/终端里这一句就是全部答案：

```text
抖音云网关客户端通道尚未接入：请等待平台提供客户端 SDK/启动参数，
当前可先用 --transport websocket（开发/备用）或 --transport static（本地联调）
```

状态为 `offline`，不会无意义重试（`retryable=False`）。

**怎么修**：这不是 bug，是"未实现"。当前可选两条路：

```powershell
# 开发/备用：自建 WebSocket
.\dist\DanmakuPet\DanmakuPet.exe --transport websocket --cloud-url ws://127.0.0.1:8000/ws/client --client-token <token> --room-id dev-room

# 纯本地：回放模拟指令
.\dist\DanmakuPet\DanmakuPet.exe --transport static --static-commands .\temp\mock-commands.jsonl --room-id dev-room
```

平台给出正式客户端通道规范后，需要开发在 `client/connection.py` 的 `PlatformTransport` 里实现，**不要在正式环境用 websocket 冒充**。

## 5. 指令下发失败

**怎么确认**

```powershell
$status = Invoke-RestMethod -Headers $headers http://<云端地址>/api/status
$status.orchestrator.gateway | ConvertTo-Json -Depth 5
$status.orchestrator.rooms[0].recent[0] | ConvertTo-Json -Depth 4
```

判读：

| 字段 | 值 | 含义 |
| --- | --- | --- |
| `gateway.mode` | 与预期不符 | 云端不是你以为的模式（`mock` 不会真的发给客户端） |
| `gateway.active` | `mock` / `wss` / `douyin_cloud` | 实际在用的实现 |
| `gateway.ws.connected_rooms` | 空数组 | wss 模式下没有任何客户端连上这个房间 |
| `gateway.douyin_cloud.last_error` | 非空 | 平台下发报错（通常是 `PlatformNotConfigured`） |
| `gateway.last_error` | 非空 | 网关内部异常 |
| `rooms[0].stats.dispatched` | 不增长 | 指令根本没发出去 |
| `rooms[0].stats.errors` | 增长 | 下发返回了失败 |

云端同时会发通知：`指令下发失败：客户端未连接或网关拒绝`。

**怎么修**

1. `GATEWAY_MODE=mock` 时**永远**不会到客户端——要么改 `wss`，要么接受"只验云端"。
2. `wss` + `connected_rooms` 为空：客户端没连上，或连的房间不是这个 `room_id`（房间号一个字符不同都算不同房间）。
3. `douyin_cloud` + `last_error` 含"未配置 DOUYIN_COMMAND_PUSH_PATH"：平台下发路径还没填，见《平台设置清单》第 8 节；**不要**猜一个路径填进去。
4. `douyin_cloud` + 平台返回 4xx/5xx：看日志里的 `平台 HTTP xxx`，按平台文档核对参数与权限。
5. 都正常但仍 `dispatched: 0`：检查是不是被**暂停**了（`rooms[0].paused=true`，暂停时新事件直接丢弃并广播 `dropped`）。

## 6. 指令过期 / 重复 / 不执行

**怎么确认**

```powershell
$room = (Invoke-RestMethod -Headers $headers http://<云端地址>/api/rooms/<room_id>).room
$room.stats
$room.recent | Select-Object -First 5 | ForEach-Object { "{0} {1} {2}" -f $_.status, $_.result_status, $_.error }
```

| 现象 | 关键字段 |
| --- | --- |
| 过期 | `result_status=expired`，`stats.timeouts` 增长；客户端日志 `指令已过期，未执行` / `排队期间指令已过期` |
| 重复 | `status=duplicate`，`stats.duplicates` 增长，通知"检测到重复消息，已跳过" |
| 不执行 | `stats.dispatched` 增长但 `completed` 不增长；客户端"最近回执"停在 `started` |
| 房间不匹配 | 客户端日志 `指令房间不匹配（指令 X / 本地 Y），已忽略` |

**怎么修**

1. **过期是设计行为**：普通弹幕 `COMMENT_EXPIRES_SECONDS=8`、礼物 `GIFT_EXPIRES_SECONDS=30`（绝对值，写在指令里）。模型慢/网络抖动就会过期，宁可丢也不演旧弹幕。若确实需要更宽松，**改云端环境变量**（8→15 之类），不要改客户端的 `COMMAND_GRACE_SECONDS` 来硬扛。
2. **重复有两条来源**：
   - 平台重推同一条消息 → 云端用 `message_id` 去重（`dedup` 命中返回 200 `duplicate: true`）；
   - 同一条消息重复决策 → 云端 `command_id` 是**由 `room_id + message_type + message_id` 哈希出来的**，同一消息必得同一 id，`DedupCache` 直接拦掉。
3. **不执行但在跑**：看客户端"最近回执"里的 `error_code`：`tts_failed`（静音动作）、`executor_error`（渲染异常）、`queue_overflow`（本地队列满，上限 8）。
4. **房间不匹配**：客户端 `--room-id` 与云端创建房间用的 id 不一致，改成完全一致。

## 7. TTS 失败

**怎么确认**：客户端状态页"TTS 错误"非空；日志 `TTS 失败，执行静音动作: ...`；回执 `error_code=tts_failed`。

```powershell
# 语音缓存目录里有没有新文件
Get-ChildItem .\assets\tts_cache | Sort-Object LastWriteTime -Descending | Select-Object -First 5 Name, Length, LastWriteTime
```

**怎么修**

| 原因 | 判断 | 处理 |
| --- | --- | --- |
| 出网被拦 | 换手机热点后立刻正常 | 放开对微软语音服务的访问 |
| 音色名不存在 | 日志含 `Invalid voice` 之类 | 换回 `TTS_VOICE=zh-CN-XiaoxiaoNeural` 或平台文档里的合法名 |
| 语速/音调格式错 | 日志含参数错误 | `TTS_RATE=+8%`、`TTS_PITCH=+0Hz`（正负号不能省） |
| 文本超长 | 回复被截到 240 字以内，一般不会 | 检查 `MAX_REPLY_CHARS` |

TTS 失败**不会阻塞队列**：会用文本长度估算时长（`500 + 字数×190ms`，夹在 1.4–15 秒）继续做静音动作。也就是说"没声音但小人在动"通常是这一类，不是音频设备问题。

## 8. 没有声音（但动作正常）

**怎么确认**

1. 状态页"语音与音频设备"：`pygame mixer` 是否"已初始化"、`音频错误` 是否为空；
2. "最近音频"显示 `xxxms · 缓存/新合成 · 路径`；路径为空说明根本没生成音频；
3. 系统音量合成器里，`DanmakuPet.exe` 的音量是否被拉到 0；
4. 直播伴侣里是否只采了麦克风、没采系统声音（见第 13 节）。

**怎么修**

| 现象 | 处理 |
| --- | --- |
| `mixer 未初始化` | 没有可用输出设备 / 被独占。插上设备、关掉独占模式的应用、重启客户端 |
| 有音频文件但听不见 | 输出设备选错；把系统默认输出改成直播伴侣要采的那个设备 |
| 只有第一句有声音 | 音频设备被其他程序抢占，重启客户端；或关掉 `TTS_CACHE` 复测是否是缓存文件损坏 |
| 声音太小/太快 | 调 `TTS_VOLUME`、`TTS_RATE`，不要靠系统音量硬拉 |
| 完全没音频文件 | 回到第 7 节（TTS 失败） |

## 9. 桌宠 helper 启动失败

**怎么确认**

```powershell
$status = Invoke-RestMethod http://127.0.0.1:8787/api/status
$status.executor.backend.desktop_pet | ConvertTo-Json -Depth 3
```

| 字段 | 异常值 | 含义 |
| --- | --- | --- |
| `state` | `starting` 卡住 | helper 起来了但没发 `ready` |
| `state` | `error` | 已确认失败 |
| `pid` | `null` | 进程不在 |
| `helper` | 路径不存在 | 打包/安装不完整 |
| `last_error` | 非空 | 具体原因 |

常见 `last_error`：

- `找不到 helper.py: ...\vendor\dafeiyu\package\runtime\helper.py` → 素材没下载（`scripts/install.ps1` / `scripts/fetch_visual.ps1`）；
- `大肥鱼 helper 在 ready 前退出` → 缺 PySide6、缺动画素材，或 `spin` 补丁没打；
- 打包版出现找不到素材 → `dist\DanmakuPet\_internal\vendor\dafeiyu\...` 不完整，重新打包。

**怎么修**

```powershell
# 源码运行：补齐依赖与素材
.\.conda\env\python.exe -m pip install -r requirements-client.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1

# 换过 dafeiyu 版本后，spin 补丁要重打一次
.\.conda\env\python.exe .\scripts\apply_dafeiyu_spin_patch.py

# 只验语音/页面，不启桌宠
.\dist\DanmakuPet\DanmakuPet.exe --no-desktop
```

注意：`--no-desktop` 时状态页会明确提示"桌面小人已关闭（--no-desktop），直播伴侣将没有画面"——这不是错误，是提醒。

## 10. 时间 / 语气 / 上下文异常

### 10.1 回答的时间差 8 小时

**怎么确认**：模型回答"现在是凌晨 3 点"，而实际是上午 11 点。

**原因**：云端用 `DISPLAY_TIMEZONE`（默认 `Asia/Shanghai`）计算"当前时间"；如果这个变量被改成 `UTC`，或者镜像里缺少时区数据，回答就会按 UTC 走。

**怎么修**：

1. 在抖音云环境变量里确认 `DISPLAY_TIMEZONE=Asia/Shanghai`，重启服务；
2. 用 `/api/status` 的 `config.display_timezone` 核对实际生效值；
3. 若启动时报 `DISPLAY_TIMEZONE=... 不是有效的 IANA 时区`，说明拼写错误或镜像缺少 `tzdata`——本项目 `requirements-cloud.txt` 已经包含 `tzdata`，重新构建镜像即可。

代码依据：`danmaku_pet/decision/llm.py` 的 `local_now()` 与 `danmaku_pet/cloud/config.py` 的 `display_timezone`。

### 10.2 语气不对、像模板回复

**怎么确认**

```powershell
$cfg = (Invoke-RestMethod -Headers $headers http://<云端地址>/api/status).config
$cfg.llm_mode, $cfg.llm_requested_mode, $cfg.llm_key_configured, $cfg.model
```

- `llm_mode=mock` + `model=mock-local`：**没有用真实模型**（Key 缺失或 `LLM_MODE=mock`），回复本来就是模板化的；
- `llm_requested_mode=deepseek` 但 `llm_mode=mock`：Key 没生效（空/错），`auto` 模式自动降级了。

**怎么修**：

1. 在云端密钥管理里配置 `DEEPSEEK_API_KEY`，重启；
2. 或用管理端 `POST /api/settings/persona` 调整角色名/身份/语气/口头禅；
3. 若日志有 `DeepSeek 初始化失败，已切到本地模拟`，按提示看具体异常（多为 Base URL 不可达）。

### 10.3 上下文混乱 / 记得不该记的

**怎么确认**

```powershell
$room = (Invoke-RestMethod -Headers $headers http://<云端地址>/api/rooms/<room_id>).room
$room.memory_rounds, $room.memory
```

**怎么修**

- 上下文**按房间隔离**，最多 `MAX_CONTEXT_ROUNDS=10` 轮，只记成功完成（`completed`）的普通弹幕；
- 需要重置：`POST /api/rooms/<room_id>/context/clear`；
- 如果两个直播间串了弹幕：检查是不是同一个 `room_id`（不同直播间必须是不同 id），云端按 id 隔离，不会跨房间共享上下文。

## 11. 平台消息返回 401 / 422

**怎么确认**：看回复的 JSON body，`error` 与 `code` 字段就是答案（`douyin/receiver.py`）。

| 状态码 | body | 原因 |
| --- | --- | --- |
| 401 | `{"error":"verification_failed","code":"bad_token"}` | `header` 模式下头里的令牌不对 |
| 401 | `... "code":"missing_secret"` | 选了 `header`/`hmac` 但没配 `DOUYIN_VERIFY_TOKEN` / `DOUYIN_VERIFY_SECRET` |
| 401 | `... "code":"missing_signature"` | 没带签名头（头名由 `DOUYIN_SIGNATURE_HEADER` 决定，默认 `x-douyin-signature`） |
| 401 | `... "code":"bad_signature"` | 签名算法/密钥不一致。云端计算的是 `HMAC_SHA256(secret, timestamp + "." + body)`，**没有时间戳头时退化为 `HMAC_SHA256(secret, body)`** |
| 401 | `... "code":"stale_signature"` | 时间戳与服务器时间差超过 `DOUYIN_TIMESTAMP_TOLERANCE_SECONDS`（默认 300 秒） |
| 401 | `... "code":"bad_timestamp"` | 时间戳头不是数字 |
| 422 | `{"error":"unsupported_payload","detail":"comment payload has no content"}` | 字段名不在候选列表里（adapter 用候选名容错，但仍可能撞上新字段） |
| 400 | `{"error":"invalid_json"}` | body 不是 JSON |
| 400 | `{"error":"room_id_required"}` | 消息里没有 `room_id`，且没有 `DEFAULT_ROOM_ID` |
| 200 | `{"duplicate":true}` | 正常：重复消息被去重（**不是错误**） |

**怎么修**

1. 先把 `DOUYIN_VERIFY_MODE` 和平台实际使用的方式对齐（平台用签名你就不能用 `header`）；
2. 签名不过时，用平台的示例消息 + 同算法在本地复算一次，确认是"密钥不一致"还是"签名字段范围不一致"；
3. 422 说明字段对不上：把**原始 body**（脱敏后）留下来，对照 `douyin/adapter.py` 的候选字段名补充映射——不要靠改平台；
4. `stale_signature` 频繁出现：检查两边时钟（云端容器时区/时间同步）。

## 12. 重复表演

**怎么确认**

- 云端 `rooms[x].stats.duplicates` 与指标 `commands_deduplicated` 是否在涨；
- 客户端"最近回执"里是否出现相同的 `command_id` 两次；
- 平台日志里是否对同一条消息重推多次。

**根因与修复**

| 根因 | 表现 | 修复 |
| --- | --- | --- |
| 平台重推，且消息**没有** `message_id` | 云端走了"复合键"去重 | 已知取舍：复合键是 `房间+类型+用户+内容+礼物+数量+时间戳(秒)`，**同一用户同一秒发相同内容会合并成一次**。要更细只能用平台稳定 id |
| 客户端重复连接同一房间 | 4409 替换旧连接，旧连接里已排队的指令可能已执行 | 保证同一房间只有一个客户端进程；重连由客户端自己做 |
| 同一条弹幕被"自动回复"和"手动回复"各触发一次 | 云端 `recent` 里两条不同 `command_id` | 这是两次**不同决策**（`command_id` 由 message_id 决定，但手动回复会生成新的 `Event` → 新 id），属于人工操作，不是 bug |
| 礼物连击 | 平台把连击拆成多条 | 用 `gift_count` 展示总数量；剧本按事件执行，属预期 |

## 13. 直播伴侣采不到画面 / 声音

**怎么确认**

1. 客户端状态页：`桌宠 ready`（不是 `starting`/`error`）、`音频 就绪`；
2. 伴侣里换"屏幕采集"看小人是否在屏幕上——在屏幕上有、窗口采集没有 = 采集方式问题，不是客户端问题；
3. 伴侣音频电平表：让客户端念一句，看是否跳动。

**怎么修**

| 现象 | 处理 |
| --- | --- |
| 窗口列表里找不到小人 | 用屏幕采集 + 裁剪；确认客户端不是 `--no-desktop` |
| 采到的是黑块 | 透明窗口不吃 alpha，改用屏幕采集；或与开发确认是否要改不透明渲染窗口 |
| 画面正常但没声音 | 伴侣里加"系统声音"采集，并确认系统默认输出就是小人发声的设备 |
| 回声/啸叫 | 关掉麦克风轨道，或让主播戴耳机 |
| 小人挡住游戏画面 | 拖到副屏/边角，或用 `PET_SCALE` 缩小（0.55–1.4） |

## 14. 日志脱敏说明（哪些会被打码，哪些不会）

**会被打码**：`ADMIN_TOKEN`、`CLIENT_TOKEN`、`DEEPSEEK_API_KEY`、`DOUYIN_APP_SECRET`、`DOUYIN_VERIFY_SECRET`、`DOUYIN_VERIFY_TOKEN`。规则是**长度 ≥4 的值**在任意日志消息里出现即替换为 `***`（`logging_setup.py` 的 `SecretMaskFilter`，云端与客户端共用）。云端的 `public_status()` 压根不返回密钥，只返回 `llm_key_configured: true/false`。

**不会被打码**（请按平台要求管理保存期限）：

- 观众昵称与弹幕内容（云端会打 `房间 X 处理事件 ... user=... text=...`，这是排障必需的）；
- 房间号、client_id、command_id；
- 模型回复文本。

所以：**不要**把观众昵称/弹幕当成可公开的数据转发；导出日志给外部时先脱敏。若平台对用户数据展示有额外要求，按《平台设置清单》第 5 节的人工确认结果执行。

另外两个刻意为之的"看不到"：

- 云端访问日志默认关闭（`--access-log` 才开），因为 `/ws?token=` 会把令牌写进 URL；
- 客户端 `hello` 帧里 `platform_params` 固定是字符串 `"redacted"`。

## 15. 测试接口在正式环境默认关闭

**怎么确认**

```powershell
# prod 下调用模拟接口
try {
  Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json" -Body "{}" `
    http://<云端地址>/api/rooms/dev-room/events/manual
} catch { $_.ErrorDetails.Message }
# => {"detail":"测试接口在当前环境已关闭（ENABLE_TEST_ENDPOINTS=false）"}  状态码 404
```

**规则**（`cloud/config.py`）：

| 环境 | 默认 | 想开怎么办 |
| --- | --- | --- |
| `dev` | 开 | 无需操作 |
| `prod` | 关 | 必须 `ENABLE_TEST_ENDPOINTS=true` **且** `ALLOW_TEST_ENDPOINTS_IN_PROD=true`（不推荐，仅临时联调） |

受此开关控制的接口：模拟评论、模拟礼物、模拟循环（start/stop）、清空上下文。**不受控制**的：`/v1/ping`、`/api/health`（均免鉴权）、`/api/status`、房间查询、`/reply`、`/interrupt`、`/pause`、`/api/settings/*`、`/api/douyin/tasks/*`——这些只要求管理令牌。

> 记得联调完把两个开关都关回去，否则等于把"随便造弹幕"的入口挂在公网上。
